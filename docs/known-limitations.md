# 已知边界与未解决的缺口

这份清单如实记录宿主目前**做不到**或**刻意没做**的事。它们不是待披露的漏洞，而是使用和评估这个项目之前应该知道的前提。

## 平台与分发

- **只支持 macOS。** 沙盒用系统自带的 `sandbox-exec`，苹果已把它标记为弃用（目前仍可用）；一旦系统移除，沙盒层需要整体替换。
- **其它平台没有操作系统级沙盒。** 非 macOS 上 pi 子进程是直接启动的，宿主只能靠收窄工具集（不给 `bash` 等工具）来限制第三方应用，这不等价于沙盒，也没有在这些平台上验证过。
- **没有签名、公证和自动更新。** 自己打的包在别的机器上会被 Gatekeeper 拦截，也没有安全更新通道。
- **pi 二进制的校验和是首次登记时信任上游的。** `scripts/fetch-pi.sh` 只接受 `src-tauri/pi-sha256.txt` 里固定的 SHA-256，发布页上的文件事后被替换会校验失败；但登记的哈希本身抄自上游发布页，上游没有提供签名，登记那一刻的真实性无法独立验证。

## 沙盒与网络

- **网络是二值的。** 不受信应用的沙盒规则拒绝全部网络，只放行它自己的那一个宿主 socket；受信应用放行全部出站网络。没有按域名过滤出网流量的能力。
- **不受信应用的 pi 无法直接请求模型服务。** 不受信应用的沙盒禁止联网，它们的 pi 发出的模型请求会以 `Connection error` 失败（`src-tauri/tests/sandbox_models_json_it.rs` 有真实 pi 的用例钉住，同时确认 pi 本身能在沙盒里正常启动）。受信应用不受此限，带自定义 provider 的完整一轮会话有真实 pi 用例覆盖。
- **应用把自己的可写目录换成符号链接，只会让它自己下一次启动被拒。** 应用对 `apps/<id>`、`sessions/<id>`、`agenthome/<id>` 有写权限，可以把它们改名后放符号链接；宿主在每次拉起（含崩溃重启）前都校验这三个目录是真实目录、且规范化后等于预期路径，不满足就拒绝启动并提示，不会把链接目标授权为可写。代价是这个应用需要用户手动清理这个目录才能再次启动。宿主在沙盒外写 agent home 时校验后立刻取目录句柄，之后的创建、改名覆盖、删除都相对句柄进行，校验后再换链也写不到别处；Maker 草稿暂存目录（预览与 `stage_write`）要求「真目录、非链接、规范化等于按字面推出的预期路径」；`filesystem` 能力授权的读写目录则逐级检查、任何一级是符号链接都拒绝（不要求大小写与 Unicode 形式和清单字面一致），通过后把规范化后的真实路径交给沙盒。两者被换链都会拒绝启动或拒绝写入，同样需要用户手动清理（用户自己建的符号链接也会被拒，这是有意收紧）。由于授权目录交给沙盒的是规范化后的路径，所以只读路径在内核里仍是「规范化，失败回退」；校验到拉起子进程之间，只有可写路径有「规范化等于自身」的字面断言兜底。这个缺口很窄，且需要同一应用另有进程在此期间运行。
- **基础规则里有三处读兜底。** 沙盒对 `/private/var`、`/private/etc`、`/private/tmp` 放行了读取，这是 macOS 运行时启动所需。

## 权限与审批

- **预声明权限挡不住提示注入。** 一个应用如果同时持有「读数据」和「出网」两种能力，不可信内容就可能驾驶它把读到的东西发出去；清单只描述能力上界，没有信息流跟踪。
- **放行规则没有参数作用域。** 「今后对此应用的这个工具自动放行」的键是（应用、连接器、工具），勾选后该工具的任意参数都会被放行，直到用户撤销。
- **自带连接器（byo）的危险分级是启发式。** 宿主不再信任这类连接器自报的「只读」注解，但读写判断依赖一张工具名前缀表，命名反常的工具可能被分错级。
- **暂存的调用参数明文落盘。** 等待审批的调用要原样重放，所以参数未脱敏地写在应用数据目录里，目录权限目前沿用系统默认值，没有额外收紧。
- **清单里的嵌套字段拼写错误会被静默忽略。** 顶层未知字段会报错，但 `system`、`filesystem` 等对象内部写错字段名时会解析成默认值（即不授予），不会提示。
- **撤销定时任务权限不会自动摘除已注册的任务。** 卸载应用会清任务，但「降权不卸载」这条路径没有对应流程。

## 技能与市场

- **危险模式扫描是静态正则。** 它能拦住常见的危险写法，拦不住有意混淆的内容；扫描通过不代表技能安全，不受信来源的技能仍然只能在沙盒里生效。
- **市场索引没有签名。** 技能压缩包有 sha256 校验且只允许 https，但哈希与下载地址出自同一份索引，索引来源本身需要用户信任。
- **市场的自定义索引地址可以指向本地文件。** 这个入口只有宿主自己的界面能调用，不暴露给应用。

## 应用间调用与调度

- **被调应用没有响应级超时。** 应用 A 调应用 B 是同步阻塞的，B 跑多久 A 就等多久。
- **应用工坊的预览会话用的是固定的安全工具集**，不是草稿自己声明的能力，所以预览通过不等于安装后行为一致。
- **被拒绝或过期的应用草稿目录不会自动回收。** 资源面板的「清理缓存」会删除 24 小时以前、且不在待确认安装里的草稿；不点就一直占磁盘，不涉及越权。

## 模型与密钥

- **应用没有明确选定 provider 时，会话拿到全部已配置的密钥。** 清单里没写 model，或只写了裸模型 id（不带 `provider/` 前缀），又没有应用覆盖和全局默认时，应用会话会拿到全部已配置的原生密钥和全部已配置的自定义 provider 密钥（`SUPERAGENT_KEY_*`），因为无法确定该用哪一家。内置的 7 个样例都写裸 `claude-sonnet-5`，默认就走这条路径。设置全局默认，或在清单里写 `provider/model`，即可收敛为只注入一家，其余原生 provider 的环境变量会被置空。
- **主会话不支持自定义 provider。** 主会话没有私有的 agent 目录，写不了 `models.json`；选了自定义 provider 时，主会话不传 `--provider`/`--model`，改为注入全部已配置的原生密钥（不含自定义）。选中的原生 provider 在钥匙串里没有密钥时，会继承宿主进程里的同名环境变量。主会话读用户主目录下的 pi 配置，那里的 `auth.json` 优先于宿主注入的环境变量。
- **用量只统计本次运行中的交互会话。** headless 会话（定时任务、应用互调）不计入；按模型拆分的数字不含工具调用与上下文压缩的开销，这部分单列为「其他」。
- **连通性测试会真实发送一条极短请求，产生少量费用。** 请求经 pi 发出以复用它的协议实现；探测时关闭了 pi 的自动重试，所以遇到偶发限流会报失败，稍后重试即可。
- **应用工坊的预览会话不经模型注入。** 预览会话拿不到钥匙串里的密钥，也不会按所选 provider 生成 `models.json`；预览里能否调用模型取决于宿主进程环境里是否本来就有密钥。
- **`providers.json` 或 `model-overrides.json` 损坏会让应用打不开。** 此时读取配置会报错并带上文件路径，需要修复或删除该文件；主会话会降级继续（忽略模型选择，注入全部已配置的原生密钥）。
- **只置空每家原生 provider 的主环境变量。** 选中某家后，其余原生 provider 的主变量会被置空；但宿主环境里的 `ANTHROPIC_AUTH_TOKEN`、`ANTHROPIC_OAUTH_TOKEN` 等其它变体不在置空范围内，仍会被子进程继承。
- **provider 目录与预设模型是 pi 0.84.4 的快照。** 它们随 pi 升级时刷新，升级之前新出现的 provider 或模型不会出现在选择列表里。

## 资源与稳定性

- **资源面板只观测，不限制。** 没有 CPU 或内存上限，失控的应用或 MCP server 仍能占满机器，只能手动关闭。面板关着时，只有空闲回收在关闭应用前会读一次内存占用。
- **CPU 是两次面板刷新之间的平均值，按单核计。** 多核满载可以超过 100%。宿主启动后第一次采样还没有 CPU 数值；面板关了很久再打开，第一个数值是这整段时间的平均，不是当下的占用。空闲回收读内存用的是它自己的采样器，不影响面板的 CPU 数值。
- **进程归属按父子关系。** 工具以守护进程方式脱离进程树（被系统接管）后，面板看不到它，关闭或回收应用也不会结束它。同样，关闭或回收只结束应用的 pi 进程，pi 名下仍在运行的子进程不会被一并结束，会被系统接管继续运行；回收通知里的「释放约 X MB」按整棵进程树估算，因此可能偏高。没拿到进程号的后台会话（定时任务、应用互调）不计入面板的资源数字，但仍会让该应用免于空闲回收。
- **空闲回收按事件判断。** 算作活动的有：打开或崩溃后自动重启、向应用发提示词或指令、pi 发出的任何事件（含回合开始与结束、工具调用）、审批回执送回应用、界面通过宿主桥保存状态；界面读取状态不算。只在界面里浏览、不触发这些操作，超过时限仍会被回收。「正在回复」从发出提示词算到收到回合结束事件；pi 若始终不发回合结束事件，该应用就不会被自动回收（偏向不误关）。回收与手动关闭一样会结束该应用的 pi 进程，重新打开是一个新会话，之前的对话上下文不带过去；应用自己的数据与状态不受影响。
- **回收前的复核与关闭不是原子的。** 维护循环在关闭前会再确认一次「仍然空闲」，但确认与关闭之间有极短的窗口；用户恰好在这一刻向该应用发出的提示词会随会话一起被关闭，需要重新打开后再发。
- **清理缓存按时间判断哪些会话文件还在用。** 没在运行的应用，会话文件整目录清空（宿主每次打开应用都是新会话，不读旧的会话文件）；正在运行的应用只保留它最早一个运行中会话启动之后（留 10 秒余量）改动过的会话文件，更早的历史会话文件会被删除；拿不到启动时刻时（含主助手）整个目录不动。应用可以改写自己会话文件的修改时间，结果只会影响它自己的会话记录。点「清理缓存」那一刻才打开的应用，或者恰好在这一刻登记进待确认安装的旧草稿，有可能被误删，窗口很窄。
- **超过 64 层的目录不统计、不清理。** 这部分不计入占用数字，面板会在对应应用旁标注「目录层级过深，统计不完整」；清理时跳过这些目录，并在清理结果里提示有几项未处理。这是为了防止被构造的深目录耗尽文件描述符。
